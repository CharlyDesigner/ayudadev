Dos ideas hacen que el Python se vea "pythónico": las **comprensiones**, que construyen colecciones en una línea, y los **generadores**, que producen valores bajo demanda en lugar de guardarlos todos. Juntas te permiten escribir código corto y que escala a datos grandes.

Prerrequisitos: la [guía de Python](/guias/python/) y la [hoja de estructuras de datos](/hojas/python-estructuras-de-datos/).

## Comprensiones: construir colecciones en una línea

Un ciclo `for` que arma una lista se puede escribir así: `[expresión for elemento in colección if condición]`.

<Ejemplo numero={1} titulo="Listas, diccionarios y conjuntos por comprensión" archivo="compr.py" ejecutar="python compr.py" salida="[4, 16, 36]
{'sol': 3, 'luna': 4, 'estrella': 8}
['a', 'e', 'l', 'n', 'o', 'r', 's', 't', 'u']">

```python
numeros = [1, 2, 3, 4, 5, 6]

# Lista por comprensión: cuadrados de los pares
cuadrados_pares = [n * n for n in numeros if n % 2 == 0]
print(cuadrados_pares)

# Diccionario por comprensión: palabra -> longitud
palabras = ["sol", "luna", "estrella"]
print({p: len(p) for p in palabras})

# Conjunto por comprensión: letras distintas
print(sorted({letra for p in palabras for letra in p}))
```

La primera línea equivale a un ciclo que recorre `numeros`, se queda con los pares y guarda el cuadrado de cada uno. Con llaves y `clave: valor` obtienes un diccionario, y con llaves sin `:` un conjunto (que descarta repetidos; por eso lo envolvemos en `sorted`). Un `for` dentro de otro, como en el último ejemplo, se lee de izquierda a derecha igual que dos ciclos anidados.

</Ejemplo>

Cuándo usarlas: cuando la transformación o el filtro caben en una línea clara. Si necesitas varias instrucciones, efectos secundarios (como imprimir) o la línea ya es difícil de leer, usa un `for` normal. Legible gana a ingenioso.

## Generadores: valores bajo demanda

Una lista guarda **todos** sus elementos en memoria. Un generador es una función que **entrega los valores uno por uno** y se pausa entre uno y otro. Se escribe como una función normal, pero con `yield` en lugar de `return`.

<Ejemplo numero={2} titulo="Un generador se pausa en cada yield" archivo="gen.py" ejecutar="python gen.py" salida="generador creado
(empieza)
3
2
(termina)
[1]">

```python
def cuenta_regresiva(n):
    print("(empieza)")
    while n > 0:
        yield n          # pausa aquí y entrega un valor
        n -= 1
    print("(termina)")


g = cuenta_regresiva(3)   # todavía no se ejecuta nada
print("generador creado")
print(next(g))
print(next(g))
print(list(g))            # consume lo que falta
```

Observa el orden de la salida. Crear el generador no ejecuta nada: aparece "generador creado" primero. El primer `next(g)` arranca la función, imprime "(empieza)" y se pausa en `yield 3`. El segundo `next` continúa hasta `yield 2`. `list(g)` consume lo que falta (solo el `1`) y al terminar el ciclo se imprime "(termina)" antes de mostrar la lista `[1]`.

</Ejemplo>

## Para qué sirven en la práctica

El gran uso: **procesar mucho sin guardar todo**. Imagina un archivo de registro de varios gigabytes. Cargarlo entero en una lista quizá no quepa en memoria. Un generador lee y entrega línea por línea.

<Ejemplo numero={3} titulo="Filtrar un registro sin armar listas intermedias" archivo="gen2.py" ejecutar="python gen2.py" salida="ERROR no hay conexión
ERROR tiempo agotado
caracteres totales: 66">

```python
# Leer un archivo enorme sin cargarlo completo en memoria
def lineas_con_error(lineas):
    for linea in lineas:
        if "ERROR" in linea:
            yield linea.strip()


registro = [
    "INFO inicio",
    "ERROR no hay conexión",
    "INFO reintento",
    "ERROR tiempo agotado",
]

# Con un archivo real: with open("app.log", encoding="utf-8") as f: ...
for linea in lineas_con_error(registro):
    print(linea)

# Una expresión generadora no crea una lista: calcula bajo demanda
total = sum(len(l) for l in registro)
print("caracteres totales:", total)
```

`lineas_con_error` recibe cualquier cosa que se pueda recorrer: una lista, como aquí, o un archivo abierto, que Python lee línea por línea. El generador solo mantiene **una línea a la vez** en memoria. La última parte usa una **expresión generadora**: es una comprensión con paréntesis en lugar de corchetes, y `sum` va tomando los valores sin crear una lista.

</Ejemplo>

## Qué recordar de los generadores

- **Se agotan.** Un generador solo se recorre una vez. Si lo necesitas dos veces, créalo de nuevo o guarda el resultado en una lista.
- **Son perezosos.** El código no corre hasta que alguien pide el siguiente valor.
- **No tienen longitud ni índices.** No puedes hacer `g[0]` ni `len(g)`.
- **Combinan con todo.** Funciones como `sum`, `max`, `any`, `all`, `sorted` y `list` aceptan generadores.

<Callout tipo="tip" titulo="Elegir entre lista y generador">
Si vas a recorrer una vez y puede ser mucho, generador. Si vas a recorrer varias veces, indexar o necesitas la longitud, lista. En la duda y con pocos datos, lista: es más simple.
</Callout>

## Errores comunes

- **Comprensiones ilegibles.** Con tres `for` y dos `if` anidados, mejor un ciclo normal.
- **Efectos secundarios dentro de una comprensión** (como `[print(x) for x in lista]`). Usa un `for`.
- **Recorrer un generador dos veces.** La segunda vez estará vacío.
- **Olvidar `yield`.** Una función sin `yield` no es un generador y ejecuta todo de golpe.
- **Convertir todo a `list(...)`.** Pierdes justo la ventaja de memoria.
